# potatOS v0.5.0（spec 0.5）

## 新增

- **名字允许命名空间冒号**：命令名和别名允许 `^[a-z0-9][a-z0-9_:-]{0,63}$`，子 agent 类型名允许 `^[a-zA-Z0-9_:-]{1,64}$`。Claude Code 风格的 `plugin:command`、`plugin:agent` 不再需要宿主在内核边界换算成 `__`。旁路会话名保持旧的 `[a-z0-9][a-z0-9_-]{0,63}`，不接受冒号。
- **宿主来源的 skill 名可以带 `:`**：Agent Skills 的命名规则仍只约束文件系统来源；宿主自己实现的 `Source` 返回 `plugin:skill` 时，会进入目录和 skill 工具的 enum，并注册成 `/plugin:skill` 命令。
- **skill 正文可由宿主改写**：`skills.Options.Rewrite` 收到会话、skill 名、触发方（`model`/`user`）、参数和展开后的正文，返回最终正文或 error。用户 `/name` 和模型调 `skill` 工具都会经过它，适合执行正文里的 `` !`命令` ``、按会话权限规则检查并把输出替换进正文。返回 error 时用 `denied` 文案结束这次加载。
- **Skill 工具支持 `args`**：模型调用可以带 `args`，正文里的 `$ARGUMENTS`、`$ARGUMENTS[N]`、`$N` 和 `$$` 按提示词命令的规则展开；不带 `args` 时正文原样加载。`kernel.ExpandPrompt` 作为公共同步展开函数导出，用户路径和模型路径共用。
- **conformance**：新增 `command_colon_name`、`subagent_colon_type`、`skill_host_colon_name`、`skill_args_model`、`skill_rewrite_model`、`skill_rewrite_user` 与 `skill_rewrite_denied` 用例；`ext/skills` 的 conformance 选项新增 `host` 和 `rewrite`。

## 行为变更

1. **pin 保存最终投递的正文**：有 `Rewrite` 时是改写后的文本；`skill` 工具带 `args` 时是展开后的文本；用户 `/name` 的 pin 和 `tokens` 也从原文改为展开后的正文。压缩后重注入的是模型实际看到的那份文本。
2. **有 `Rewrite` 时模型路径每次加载都先执行改写器，再按本次改写后的正文判重**：输出相同才返回 `already_active`，输出不同就返回新正文并更新 pin。这样重复调用能看到最新的 `!` 输出；代价是每次调用都会执行改写器，宿主可在 `Rewrite` 内部按会话做缓存。带 `args` 的调用也按最终正文判重。
3. **没有 `Rewrite` 时保持原来的同正文判重**；带 `args` 的调用按展开后的正文判重，参数或正文不同会重新加载。
4. **Skill 工具 schema 多了 `args` 属性**；不传 `args` 的旧调用行为不变。

## 迁移

- spec 从 0.4 对齐到 0.5；SDK `v0.5.0` 满足 spec 0.5，`v0.5.y` 都满足 spec 0.5，全部 conformance 用例已迁移。
- 已有命令名、子 agent 类型名和 skill 名不受影响；需要 `:` 的宿主可以直接使用真实名字，不再需要双向换算。
- 宿主自己实现的 `Source` 返回带 `:` 的名字时，现在会注册命令；如果不想暴露命令，继续让该 skill 的 `UserInvocable` 为 false。
- 用户路径的 pin/tokens 在正文含 `$ARGUMENTS` 或 `$$` 时会与 0.4 不同；依赖旧 pin 文本的宿主需要检查。
- 旁路会话名仍不接受 `:`，与 `runtime.md` §12.8 一致。
