# potatOS v0.2.0（spec 0.2）

## 新增

- `Session.Tools()` / `Session.HostedTools()`：握手时读取当前可见的工具，排序、遮蔽与 `Hide` 语义和 `Commands()` 一致（#5）。
- `WithApproverNamed(name, fn)`：审批者可以命名，链顺序仍由 `Priority` 决定（#6）。
- `Session.ApprovalRules()`：导出有效规则，带 `Scope` 与 `Portable`，审计能回答“命中的是 agent 还是 session 的策略”（#11）。
- `approval.requested.rules[]` 与审批 hook 收到的 `Rules[]`：每项新增可选 `Scope`（`agent|session`），审批 UI 不必再反查注册代码就能区分规则来自哪一层（#11）。
- `Registrar.ApprovalRule`：运行期增删规则，从下一次 gate 生效，并发出 `registry.changed{kind:"approval_rule", effective:"now"}`（#3）。
- `RunCancelable`：break 或 ctx 取消时停掉已开始的 turn、撤回还在队列的输入；`Run` 语义不变（#10）。
- `WithTexts`：覆盖 `spec/prompts/reminders.md` 的固定文本与提示词文件，provider 适配器通过 `provider.Request.Texts` 共用同一份；`system.core` 的覆盖会校验运行时标签（#2）。
- `event.Notice.Kind` / `Detail`：内核自己发出的通知可以结构化翻译（#2）。
- `model.anomaly`：流式输出中的重复（短周期、整行、整段）会发 advisory 事件，默认开启，`AnomalyConfig{Disabled: true}` 关闭（设计 §4.11）。

## 行为变更

1. **跨 scope 同 id 的规则从“静默共存”变为启动失败**：`NewSession` / `Resume` / `ChildOf` 与运行期新增都会返回 `ErrDuplicate`，并指出冲突的 id。
2. **带原生谓词的规则不能序列化**：`ApprovalRule.MarshalJSON` 在有 `Match` 时返回 error；`ParseApprovalRules` 拒绝规则文件里的 `match` 字段，不再静默忽略成“匹配全部”。
3. **谓词 panic 不再打到 gate**：`deny` / `ask` 视为命中，`allow` 视为不命中，并记日志。

## 迁移

- 规则 id：给 session 级和 child 级的 id 加命名空间（如 `sess:...`、`child:...`），否则升级后会启动失败。
- spec：从 `0.1` 对齐到 `0.2`。spec 不发 PATCH，`v0.2.y` 都满足 spec `0.2`；会话文件第一行的 `spec_version` 只记录不校验，旧的 `0.1.0` 文件仍可恢复。
- 文本覆盖：如果只想本地化，优先覆盖固定文本；`system.core` 保留 `runtime_tags.json` 的每个标签与 `</runtime-conventions>`。
- `model.anomaly` 不需要处理：不监听就没有任何行为差异；要干预可以在收到事件后 `InterruptTurn`，或等 `message.completed` 再拒绝整条回复。

- `go test ./...` 全绿，含全部 conformance、扩展用例与新增的 `loop/approval_rule_predicate`。
