# potatOS v0.3.0（spec 0.3）

## 新增

- **运行期改窗口**：`Session.SetContextWindow(n)`，以及创建/恢复时的 `kernel.SessionContextWindow(n)`。`ContextPolicy.MaxContextTokens` 现在直接指定窗口，不再与模型能力取小；`AutoCompactRatio` 算出的阈值跟着新窗口重算。一轮进行中修改，从该轮的下一次模型调用起生效，`sess.Context()` 立刻反映；窗口写入会话文件（`context_window`），`Resume` 自动恢复，分叉沿用源会话的窗口。
- **按输入截断**：user 行记录本次投递的 `input_ids`。`Rewind(ctx, id)` 和 `ForkAt(id)` 现在接受输入 id，包括 `ModeNextLoop` 在一轮中间注入的行；轮次 id 继续可用。几条输入被合并进同一行时，截到该行之前，这些输入一起丢弃。`RewindReport.InputID`、`TurnInfo.InputID` 和 `context.rewound.input_id` 让宿主知道这次截断是按哪条输入定位的。
- **subagent 调用时选模型/强度**：`Options.Models`、`Options.Efforts`、`Options.ResolveModel` 让宿主声明可选项并解析成 `ModelRef`；`Def.FixedModel` 固定跟随父会话或定义里的模型；工具 schema 只在声明了列表时暴露 `model` / `effort`。`subagent_start` 的输入和输出都带这两个字段，continuation/restart 沿用首次保存的选择。`inherit` 内建，不需要宿主解析。

## 行为变更

1. `ContextPolicy.MaxContextTokens` 从“上限”变为“精确窗口”：设了就用它，可以比模型报告的窗口大，0 仍跟随模型。原来把它当上限、且设得比模型窗口大的配置，升级后会按设定值发请求，靠 overflow 压缩兜底。
2. `usage.updated` 的 `window_tokens` 现在报会话的有效窗口，不再固定报模型能力窗口；`ContextReport.Window`、`Usable`、`Threshold` 三者一致。
3. `RewindReport.TurnID` 现在是被丢弃那一行所属的轮次；轮中截断时它可能早于截点。`Dropped` 和 `Input` 描述的是被丢弃的那一行。
4. subagent 的定义固定了模型时，调用里的 `model` / `effort` 会被忽略，不报错；hook 改写这两个字段时不按枚举校验。

## 迁移

- 0.2 的会话文件可以直接恢复。旧行没有 `input_ids`，升级后只能按轮次回退；升级后新写入的行才支持按输入 id 截断。
- 原有 `Rewind(ctx, turnID)` 和 `ForkAt(turnID)` 调用不用改。要按消息回滚/分叉时，把该消息对应的输入 id 直接传进去。
- 如果宿主依赖 `window_tokens` 等于模型窗口，改用 `ContextReport.Window` 或自行记录；设置窗口后 `window_tokens` 会变。
- spec 从 0.2 对齐到 0.3；SDK `v0.3.0` 满足 spec 0.3，`v0.3.y` 都满足 spec 0.3。
