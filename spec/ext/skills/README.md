# ext/skills

Agent Skills (`<name>/SKILL.md` directories, as the Agent Skills specification defines them) listed in the system prompt, loaded by the model with the `skill` tool or by a person with `/<name>`. The tool definition is `skill.json`; every other text the model sees is a section of `texts.md`, rendered by the template language of `runtime.md` §7.

- **Sources.** A file-system source walks its root at most 4 directories deep and 2000 directories in all, skipping `.git` and `node_modules`; a directory holding `SKILL.md` is a skill, and its subdirectories are its resources, not further skills. `SKILL.md` starts with a `---` line; the frontmatter runs to the next `---` line, and the body is the rest with surrounding whitespace removed. Known fields: `name`, `description`, `license`, `compatibility`, `metadata` (a map of strings), `allowed-tools` (split at whitespace and at commas outside parentheses, or a list), `user-invocable` (default true) and `disable-model-invocation` (default false); any other field is kept verbatim. The default parser reads `key: value` pairs, where a plain value keeps every colon in it, single- and double-quoted values, `|` and `>` block scalars without their trailing line breaks, and one level of nested map or list. When a parser fails, the frontmatter is parsed once more with every plain top-level value that contains `": "` double-quoted. A skill without a description, whose frontmatter never parses, or whose name breaks the naming rules (lowercase letters and digits joined by single hyphens, at most 64 characters) is skipped; one without a name takes its directory's; a name that differs from its directory is kept with a warning. Of two skills with one name in a source, the first in walk order wins. A skill's location is its `SKILL.md` path from the root, and its resources are its other regular files, paths relative to its directory, in byte order. The Agent Skills naming rules bind the file-system source only; a host source names its skills itself, and a name that fits a command's rule (a `:` may separate a namespace) gets its `/<name>` command.
- **Resource paths** are relative, valid slash-separated paths without `.` or `..` elements, backslashes, `%` or `:`, naming a regular file reached without a symbolic link inside the skill's directory. Anything else is invalid.
- **The catalog** is the extension's sources merged in order, the first source with a name winning (a shadowed one is logged), sorted by name. It is listed when the extension is installed and again whenever a source is added or removed.
- **Catalog section** (`skills`, catalog slot): empty without a model-invocable skill, else `catalog`, `{{skills}}` one `catalog_item` per model-invocable skill joined by line breaks, with the description cut to `max_description_chars` code points (1536 by default) and `&`, `<`, `>` in every value written `&amp;`, `&lt;`, `&gt;`. Like every section it is rendered when an epoch starts.
- **The `skill` tool** is registered, in parallel mode, while the catalog has a model-invocable skill; its `name` enum lists those names in byte order at every freeze point. A call is checked against the current catalog: a name that is not a model-invocable skill gives an error with `unknown_skill`, `{{names}}` the model-invocable names joined by `, `. A call may add `args`; the body then expands as a prompt command's template (`runtime.md` §6) with them. Without `args`, the body is delivered as written.
- **Rewriting.** A host may set a rewriter: it receives the session, the skill's name, the trigger (`model` or `user`), the arguments and the body after `$ARGUMENTS` expansion, and returns the body to deliver or an error. An error ends the load with `denied` as the text for the person or the model. It is not called for a resource, or for an already-active load that names no `args`.
- **Loading** (`name` alone, with optional `args`) fires `skill_activate`; a deny gives an error with `denied`. When the session's pin set already holds the pin `skill:<name>`, a call without `args` is `already_active` if a rewriter is set or the pin's body equals the delivered body; a call with `args` is `already_active` only without a rewriter and when that body matches, since a rewriter may return different text on every invocation. Otherwise it is `content` (`{{name}}` and `{{location}}` as JSON strings, the body with `</skill_content>` written `<\/skill_content>`), followed on the next line, when the skill has resources, by `resources` with one `resource_file` per path. The result declares the pin `skill:<name>` with the delivered body and `max_tokens` the extension's pin tokens (5000 by default).
- **A resource** (`name` and `resource`) is read without firing the hook or pinning, and a call with `resource` ignores `args`: an invalid path gives an error with `invalid_resource`, a missing file an error with `no_resource`. At most 262144 bytes are read, ending before an incomplete code point at the limit; text with a NUL byte or invalid UTF-8 gives an error with `resource_binary`, and a longer file gets `resource_truncated` on the line after the text, `{{limit}}` 262144.
- **`/<name>`** is registered for each user-invocable skill whose name is free; a taken name leaves the skill without a command and logs a warning. Installed at agent scope, the extension registers these commands when the first session starts, in a `session_start` hook named `skills` that it then removes, so that the host's own commands, installed after every extension, keep their names; installed at session scope, it registers them at once. Its description is the skill's, cut like the catalog's, and its argument hint the `argument-hint` field. It fires `skill_activate` with trigger `user`; a deny ends the command with `denied` as its text. Otherwise the body expands as a prompt command's template (`runtime.md` §6), a rewriter receives the expanded body and its arguments and returns the command input's body or an error (which ends the command with `denied` as its text), and the command input is that body; it declares the same pin in memory with the delivered body.
- **A change of the catalog** reaches the open sessions of the scope the extension is installed at as an announcement (`runtime.md` §5.1) with source `ext:skills`: `added` followed by one `added_item` per added model-invocable skill, and after a blank line `removed` with every removed name joined by `, `, each part only when it has names. The tool's enum and the commands follow at once; the catalog section changes with the next epoch.
- **Hook point** `skill_activate`, keyed on the skill's name (10 s, open), takes `{name, trigger, allowed_tools}` with the hook environment and answers `{deny, reason}`; a deny ends the chain.
- **Events.** `skills.activated{name, trigger, tokens, deduplicated, allowed_tools}` for every load and command, `tokens` the estimate of the body the result carries, or of the pin's body when deduplicated, by the runtime's text heuristic (`runtime.md` §12.1); `skills.catalog_changed{added, removed}`, every skill's name in byte order, published with the announcement.
