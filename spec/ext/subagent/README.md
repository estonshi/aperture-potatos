# ext/subagent

The `subagent` task kind with its start tool, and `ask_parent` in the child session. The tool definitions are `subagent.json` and `ask_parent.json`; every other text the model sees is a section of `results.md`, rendered by the template language of `runtime.md` §7.

- **Types.** The extension's definitions, or one named `general` described by `general` when it has none, plus those defined later at agent or session scope, a session's shadowing its agent's of the same name. The start tool's `agent_type` enum lists a session's types in name order, and its description gets a blank line, `types`, and one `type` line per type in that order. A call naming a type the session does not have is an error result with `unknown_type`, `{{types}}` the names in order joined by `, `. A type defined at session scope gives that session its own start tool, whose enum has the session's types too.
- **The start tool** is the kind's start tool (`runtime.md` §13.6), with the kind's capabilities `instructions`, `continue` and `restart`: `description` is the task's title, and the input without `background` is the task's input.
- **An attempt**, in order: in a subagent's child session it fails with `nested`; a type the session no longer has fails with `unknown_type`; it takes one of the owning session's slots, at most `max_concurrent` (8 by default, a negative value lifting it) attempts foreground and background together, or fails at once with `too_many`, `{{max}}` the limit.
- **A first attempt or a restart** fires `subagent_start`; a deny fails the attempt with `denied`, `{{reason}}` the hook's reason. It then derives the child's agent (`runtime.md` §13.10): named after the type, with the type's description, the type's instructions as its user section, the type's model or else the owning session's current one, the type's max steps or else 50, the owning session's tools without `subagent` and narrowed by the type's `tools` (all when unset) and `deny_tools`, and all the parent's hooks. It opens the child session under the attempt, with `ask_parent` at session scope when the type's tools allow that name, and saves the state `{"child_session_id","agent_type"}`.
- **A continuation** goes on with the child that is still open, or resumes it from the store; with neither it fails with `cannot_continue`.
- **Input.** The prompt (a hook's `updated_prompt` if any) or the continuation's instruction goes to the child as agent input from `agent:<the owning session's agent name>`. A hook's `additional_context` goes before it as a reminder that does not wake, source `hook:subagent_start`. An instruction the attempt receives goes to the child the same way in its mode; an answer while `ask_parent` waits goes to that call instead.
- **The end.** When the child is quiet (`runtime.md` §13.6) with no instruction waiting, `subagent_stop` may continue it, its reason sent as the next agent input, at most 8 times per attempt. Otherwise the attempt ends with the child's last turn: an `error` outcome fails it with the turn's error; any other outcome gives the summary, the final text sanitized as foreign (`runtime.md` §13.7), and the content `result`, `{{text}}` that text or `no_answer` when it is empty, followed after a blank line by `not_completed` when the outcome is not `completed`, with `</subagent_result>` in it written `<\/subagent_result>`. The result's data is `{"child_session_id","outcome","steps","usage"}`.
- **A stop** interrupts the child's turn, waits 100 ms for it to wind down, and closes the child, so a later continuation resumes it.
- **`ask_parent`** (serial, no timeout) asks the owning attempt `question` (`runtime.md` §13.4) and waits: the result is the answer's text. With the type's `ask_timeout` set, when it passes first the question is withdrawn and the result is `ask_timeout`, `{{duration}}` the timeout in whole seconds rounded up followed by `s`; an answer that arrives later goes to the child as input. When the attempt that owned the child has ended, the result is `no_one_to_ask`.
- **Hook points**, keyed on the type. `subagent_start` (10 s, closed: a failing hook denies with the reason `subagent_start hook failed (<kind>)`, the kind being `timeout`, `error` or `panic` and never the error text) takes `{task_id, attempt, agent_type, prompt}` with the hook environment and answers `{deny, reason, updated_prompt, additional_context}`; a deny ends the chain, a rewritten prompt is what later hooks see, and contexts join with a blank line. `subagent_stop` (30 s, open) takes `{task_id, agent_type, outcome, last_assistant_text, continuations}` and answers `{continue, reason}`; any continue continues, reasons joined with a blank line. Neither output has the kernel's common fields, since their context belongs to the child.
