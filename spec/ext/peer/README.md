# ext/peer

The `a2a` task kind with its start tool `a2a_send`, the `<available_agents>` catalog, in-process peers, and the client for remote A2A agents (`a2a.md`). The tool definition is `a2a_send.json`; every other text the model sees is a section of `texts.md`, rendered by the template language of `runtime.md` §7.

- **Peers.** A peer has a card (name, description, version, skills, whether it streams, its url) and four operations: send a message and read the round's events, subscribe to a task (its first event is the task as it is now), cancel a task (best effort; a task that cannot be canceled is not an error) and its card, which never does I/O. Events are a task snapshot, a message, a status or an artifact chunk, with the task's and context's ids. A round ends at a message, or at a status whose state is terminal (`completed`, `failed`, `canceled`, `rejected`) or interrupted (`input_required`, `auth_required`); a task snapshot is followed by its artifacts and, when its state ends the round, by a status. A peer refusing the request for credentials ends it with an auth error carrying the HTTP status and the challenge; a peer that no longer knows a task ends with an unknown-task error.
- **Registration.** The extension registers the kind with the capabilities `instructions`, `continue`, `restart` and `inspect`, the catalog section, and its peers; more are registered later in its scope or, under an agent that has it, at session scope, a session's peer shadowing its agent's of the same name. The name the model uses is the card's name (or the name a host gave the peer instead, which leaves the rest of the card as it is) with every character outside `[a-zA-Z0-9_-]` replaced by `_`, cut to 64, `agent` when empty; a second peer of the same name in one scope is refused as a duplicate. `a2a_send` is registered while a scope has peers; a session's own tool lists the agent's peers too. A change in an open session's peers is announced as a reminder that does not wake, source `peer`: `added` with one `added_item` line, or `removed`.
- **The catalog** (catalog slot, rendered at the start of an epoch) is left out when the session has no peer; otherwise it is `catalog`, `{{agents}}` one `catalog_item` per peer in name order joined by a newline. `{{description}}` is the card's description sanitized as foreign (`runtime.md` §13.7) with `&`, `<`, `>` escaped; `{{skills}}` is empty, or `catalog_skills` followed by a newline, `{{skills}}` one `catalog_skill` per card skill, `{{name}}` its name (its id when unnamed) in double quotes with `&`, `<`, `>`, `"` escaped and `{{description}}` its description on one line, escaped like the agent's.
- **`a2a_send`** (parallel) is the kind's start tool (`runtime.md` §13.6). Its `agent` enum lists the session's peers in name order. A call naming a peer the session does not have is an error result `unknown_agent`, `{{agents}}` the names in order joined by `, `. The call chain is the JSON list of agent names in the turn's input metadata `agent_call_chain`, followed by this session's agent name unless it is already last; a call whose peer is on it is an error result `cyclic`, `{{chain}}` the chain and the peer joined by `→`. Otherwise the input, with `chain` set to the chain, is the task's input; the title is the peer's name, `: ` and the first 60 code points of the message on one line.
- **An attempt** fails with `agent_gone` when the session no longer has the peer (for a continuation, the one its state names), and with `cyclic` when the peer is on the input's chain (the session's agent name alone when it has none). Each message carries a new message id, role `user`, one text part and the metadata `agent_call_chain`. The state, saved whenever the peer names a new context or task, is `{peer, context_id, task_id, protocol_version}`; the session also remembers, per peer, the context of its latest exchange, and after a resume rebuilds it from the task with that peer whose attempt started last.
- **A first attempt** sends the message in the peer's latest context, or in none with `new_conversation` or after a restart. A **continuation** asks the peer for the task its state names: one waiting for input gets the instruction as its answer (with the task and context ids); one still working is followed to the end of its round, the instruction held; one waiting for credentials, or an auth error from the subscribe, is handled as under **Credentials** and the task is asked again, through the stream that answers the metadata when the hook gave any; a terminal one, or one the peer no longer knows, gets the instruction as a new message in the same context; without a task id the instruction goes in the saved context, or in none.
- **One exchange per conversation.** In a session, a message in a context waits until no other exchange of that peer and context is in a round, in the order they asked; a waiting attempt reports `waiting`, `{{task_id}}` the attempt holding the conversation. An attempt holds it from sending until the round ends, keeps it while it has held instructions to send, and lets it go while it waits for input. A new conversation takes it once the peer names its context.
- **Instructions** that arrive during a round are held: `queue` ones in a queue, the others in order in a merge list, and an `interrupt` also cancels the peer's task when it has one. After a round, the merge list goes out as one message, the texts joined by a blank line, then each queued one alone, in the same context without a task id. Held instructions are reported to the runtime, so an attempt that ends early lists them as unprocessed.
- **Round ends.** A message, or `completed`, adds a reply: the reply text is the artifacts' texts in the order they first appeared joined by a blank line, then the final status message when it differs; parts that are not text are written `[file <name> (<media type>, <n> bytes)]`, `[url <url>]` or their data as JSON. The reply is sanitized as foreign, `no_reply` when empty, with `</agent_reply>` written `<\/agent_reply>`, and becomes the content block `reply`, `{{agent}}` and `{{task_id}}` quoted with `&`, `<`, `>`, `"` escaped. `canceled` after an interrupt from this side adds nothing. `input_required` asks the runtime the status message sanitized as foreign, or `needs_input`; the first instruction accepted as the answer goes to the same task and context, after the merge list joined by a blank line. `auth_required` fires `peer_auth_required`. Any other end fails the attempt with `ended` or `ended_with`, `{{message}}` the status message sanitized as foreign.
- **The result** is the replies: the summary their texts joined by a blank line, the content one block each, the data `{peer, context_id, task_id, state}`. A failure keeps the replies so far as a partial result. A stop cancels the peer's task when it has not ended, within 2 seconds.
- **Progress.** Each event of a round is reported: the text is the status message, or the last 200 code points of the artifact being received, sanitized as foreign; the data is `{state, context_id, task_id}`. A change of state is reported at once, the rest at most every 500 ms. Inspecting a running attempt with a task asks the peer (subscribe, first event); otherwise it gives the last report.
- **Credentials.** An auth error, or a round ending in `auth_required`, publishes `peer.auth_required{peer, task_id, context_id, status, detail, attempt}` under the task's hop and fires `peer_auth_required` (keyed on the peer, 10 minutes, open), which takes `{peer, task_id, context_id, status, detail, data, attempt}` with the hook environment and answers `{retry, metadata, reason}`; the first retry ends the chain. On a retry, a refused request without a task is sent again with the same message id, and one with a task follows it with subscribe; a task waiting for credentials gets the hook's metadata in a message without parts first, when there is any, then is followed. Without a retry, or after 3 in one attempt, the attempt fails with `auth_failed`, and a task waiting for credentials is canceled first.
- **In-process peers** expose another agent: its nickname and description are the card, and it streams. A message without a context opens a session of that agent, whose id is the context; a closed context is resumed from the agent's store, or replaced by a new session whose id the events carry. A message is input from `peer:<the sending session's agent name>`, or `peer` without one, in `queue` mode with the metadata `agent_call_chain`, so it is a turn of its own; the input id is the task id. Its events: `task{submitted}` at once, `status{working}` when its turn starts, the text deltas of the turn's own steps as the `reply` artifact (each step's first chunk replacing, the rest appended), and at the turn's end the turn's final text as the whole `reply` artifact with `last_chunk`, then the status: `completed` for completed, max steps, max tokens, refused and hook stopped (with `outcome` as its message unless completed), `failed` with the error for an error, `canceled` for interrupted or canceled, `rejected` (without the artifact) for a dropped input. When an `a2a` task drives it, every event of that turn and of the work under it is relayed under the task's hop, and the turn's model calls are recorded in the sending session's ledger under the bucket `peer` and the attempt's turn. Cancel interrupts that turn, or the turn as soon as it starts. Sessions close after 30 minutes idle, and the least recently used idle one closes when 64 are open.
